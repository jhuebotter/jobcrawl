# JobCrawl Constitution

## Core Principles

### I. Intent-First Specification
Specifications MUST define what problem is being solved and why it is important before defining how to solve it. The scope of any specification MUST be minimal and clear.

### II. Privacy-by-Design & Local-First
All processing and data storage MUST be local by default. Any use of remote data or services MUST be transparent to the user and require explicit consent.

### III. Provenance & Traceability
Every dataset, model, and decision generated by the system MUST be auditable and reproducible. The origin and transformation of all data MUST be tracked. Record source URLs and retrieval timestamps for all derived data.

### IV. Simplicity & Modularity
The system MUST be composed of small, independent, and composable components. Features that are not essential to the core problem MUST NOT be implemented. Premature abstraction is forbidden.

### V. Quality Gates & Review Discipline
All work MUST pass through lightweight validation, acceptance checklists, and peer review before being advanced to the next stage of development. Acceptance checklists are mandatory at the Specification and Plan stages; subsequent stages verify against those checklists.

## Additional Constraints & Standards

- **OS Agnostic:** The system MUST operate consistently across macOS, Linux, and Windows.
- **Open Formats:** All data MUST be stored in open, reproducible formats.
- **Determinism:** System behavior MUST be deterministic where possible.
- **Documentation:** Functional changes MUST be accompanied by corresponding documentation changes.
- **Randomness:** Randomness MUST be seeded where feasible to support reproducibility.

## Development Workflow & Review Process

The development process follows a strict Spec-Driven Development loop:
1.  **Specification:** Define the what and why.
2.  **Clarification:** Refine the specification through questions and feedback.
3.  **Plan:** Create a detailed implementation plan.
4.  **Tasks:** Break the plan into actionable tasks.
5.  **Implementation:** Write the code.
6.  **Verification:** Ensure the implementation meets the specification.

This constitution serves as the primary review gate for all stages of the workflow.

## Governance

- **Simplicity & Transparency:** All rules and processes MUST be simple and transparent.
- **Amendment Process:** Amendments to this constitution require a documented rationale, approval from the project maintainers, and an update to the version and date.
- **Default decision rule:** prefer local, simple, transparent solutions when trade-offs arise.
- **Decisions with lasting impact** MUST be logged and tied to a concrete artifact (spec, plan, or tasks).
